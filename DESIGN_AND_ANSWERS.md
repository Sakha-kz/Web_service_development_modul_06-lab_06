# Отчёт и результаты тестирования: Модуль 06 (Лабораторная работа / СРСП)

## 📌 Архитектурные особенности решения

1. **Аутентификация через JWT:**
   - Для идентификации пользователей используется механизм JSON Web Token (RFC 7519).
   - Токен формируется в `AuthController` с криптографической подписью HMAC-SHA256 (`HmacSha256Signature`).
   - В токен внедрены клеймы:
     - `ClaimTypes.Name` = `"student"`
     - `ClaimTypes.Role` = `"User"`
     - `JwtRegisteredClaimNames.Jti` = уникальный идентификатор GUID.
2. **Селективная защита эндпоинтов:**
   - Публичные операции чтения списка (`GET /api/tasks`) и отдельной задачи (`GET /api/tasks/{id}`) снабжены атрибутом `[AllowAnonymous]`.
   - Мутирующие операции (`POST /api/tasks`, `DELETE /api/tasks/{id}`) снабжены атрибутом `[Authorize]`.
3. **Работа с контекстом пользователя:**
   - При выполнении запроса `POST /api/tasks` сервер считывает `HttpContext.User.Claims`, извлекает имя пользователя и автоматически фиксирует его в свойстве `TaskItem.CreatedBy`.

## 📊 Матрица проверки безопасности (Задание 9)

| № | Проверка / Сценарий | Метод и URL | Авторизация | Ожидаемый результат | Фактический результат | Статус |
| :-: | :--- | :--- | :--- | :-: | :-: | :-: |
| **1** | GET без токена | `GET /api/tasks` | Отсутствует | `200 OK` | `200 OK` | Успешно |
| **2** | POST без токена | `POST /api/tasks` | Отсутствует | `401 Unauthorized` | `401 Unauthorized` | Успешно |
| **3** | POST с корректным JWT | `POST /api/tasks` | `Bearer <valid_token>` | `201 Created` | `201 Created` | Успешно |
| **4** | DELETE с корректным JWT | `DELETE /api/tasks/1` | `Bearer <valid_token>` | `200 OK` | `200 OK` | Успешно |
| **5** | Запрос с изменённым JWT | `POST /api/tasks` | `Bearer <tampered>` | `401 Unauthorized` | `401 Unauthorized` | Успешно |
| **6** | Запрос с истёкшим JWT | `POST /api/tasks` | `Bearer <expired>` | `401 Unauthorized` | `401 Unauthorized` | Успешно |

## 🔍 Пример содержимого Claims в декодированном JWT

### Header (Заголовок):
```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

### Payload (Полезная нагрузка):
```json
{
  "http://schemas.xmlsoap.org/ws/2005/05/identity/claims/name": "student",
  "http://schemas.microsoft.com/ws/2008/06/identity/claims/role": "User",
  "jti": "5a4b7c12-3f89-4e78-9b0d-1c2e3f4a5b6c",
  "nbf": 1729158000,
  "exp": 1729161600,
  "iss": "TaskManagementApi",
  "aud": "TaskManagementClient"
}
```

## 💡 Краткий вывод по выполненной работе

В ходе выполнения лабораторной работы:
1. Освоена настройка конвейера аутентификации и авторизации ASP.NET Core с использованием `Microsoft.AspNetCore.Authentication.JwtBearer`.
2. Реализована безопасная процедура логина с генерацией симметрично подписанного JWT токена и установкой срока его жизни.
3. Организовано разграничение доступа: методы чтения доступны публично, операции создания и удаления защищены строгой проверкой подписи и срока действия токена.
4. Реализовано извлечение утверждений (`Claims`) из контекста текущего пользователя (`HttpContext.User`), что позволило прозрачно аудировать автора создаваемых задач.
